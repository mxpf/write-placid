# Write Placid Core 1.7.0

This release adds optional one-line summaries, safer private draft updates, and stronger checks that published writing matches the version saved in Studio.

## What changed

- **One-line summaries.** Studio's **Optional dek** field saves a short summary with the writing. Drafts MCP can set, replace, preserve, or clear it through `dek`. When publishing is enabled, Site shows the summary below the title and uses it in page previews and RSS. Writing without a summary keeps the first paragraph as its description.
- **Private drafts in the demo.** Drafts save in D1 and reopen in a fresh tab. MCP updates keep the same draft and preserve a Studio-edited summary when `dek` is omitted. Missing or ambiguous draft names and pieces with publication history return an error. **Delete** keeps a private recovery copy, including the summary and body.
- **Publication checks.** Studio checks the exact editor revision against fresh kDrive content, verifies the GitHub snapshot and branch, and confirms the deployed revision before reporting **Live now**. Live checks also work for sites under a path such as `/writing/`.
- **Safer saves.** Studio can recover edits to different fields and insertion-only changes without discarding newer writing. Competing edits that cannot be combined still return a conflict.
- **Accessibility and development checks.** This release includes accessibility fixes, dependency updates, and checks that run in PowerShell on Windows as well as macOS and Linux.
- **Clearer setup guides.** The guides explain the separate demo Studio and Drafts MCP, private drafts, summaries, recovery copies, and disabled publishing.

## Upgrading an existing installation

Public snapshot contract `1` is unchanged. Summaries are optional, so existing Markdown does not need a `dek` field.

1. Back up your writing and private recovery state before upgrading. Pin the verified `mxpf-write-placid-core-1.7.0.tgz` release artifact and update the consuming app's lockfile.
2. Update Site and Studio together. A custom Studio client must send the complete editor document to the Publish endpoint and pass the published revision to the live check. Older requests containing only a document ID are no longer enough to verify publication.
3. If you build document objects directly, include empty `dek` and `publishedRevision` values when those fields have no value. Studio stores them in the existing D1 editorial JSON field.
4. Run the [release and downstream checks](../CORE.md#release-gate) for your installation before deploying. Keep its identity, credentials, storage bindings, and publishing settings in place.

The demo keeps publishing disabled and **Publish** hidden. Preparing this release does not publish writing, change the demo's publishing settings, or update any other installation.
